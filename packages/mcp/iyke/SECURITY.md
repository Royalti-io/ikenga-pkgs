# Security Policy

## Reporting a Vulnerability

If you believe you've found a security vulnerability in `@ikenga/mcp-iyke`, please do not create a public issue. Instead, send an email to **security@royalti.io** with the following information:

- What component or endpoint (e.g., `iyke_go`, HTTP transport) is affected. 
- Detailed steps we can follow to reproduce the behavior.
- The version of `@ikenga/mcp-iyke` and the host operating system where you observed the issue.
- Any logs, stack traces, or network captures that illustrate the impact.

We will acknowledge receipt within 2 business days and follow up with you during the investigation.

## Supported Versions

`@ikenga/mcp-iyke` is supported in the published `0.1.x` release line. Please upgrade to the latest patch release before reporting a vulnerability.

## What We Don’t Do

- We do not accept unsolicited penetration-testing or discovery data that violates third-party terms of service.
- Do not share Proof-of-Concept exploit code publicly until the vulnerability is resolved and we give permission.

## Handling a Report

1. We triage the report within 2 business days and acknowledge once we reproduce it.
2. Critical or high-severity issues receive a fix branch and patch release.
3. We will coordinate disclosure timing and provide CVE assignment when appropriate.
4. After the release, we will credit you unless you request anonymity.
